## Context

### 왜 바꾸는가

2026-08-13 미팅에서 이띠 측이 **ROE 수치 오류**를 지적했다. 원인을 실측으로 추적한 결과 **계산 버그가 아니라 산정기준 불일치**였다. 같은 회사·같은 연도에 서로 다른 ROE가 최소 3개 존재한다.

**KB금융 FY2025 실측**

| 값 | 출처 | 산식 |
|---|---|---|
| **9.93** | 사업보고서 원문 「5. 재무건전성 등 기타 참고사항」 | 회사가 감독기준으로 산출·공시 (재현 불가) |
| **9.682** | DART 재무지표 API `M211550` ← **프로토타입 현행** | 당기순이익(전체) ÷ 평균 자본총계 |
| **9.59** | 이띠 연구원 엑셀 `금융업 발라내기.xlsx` FS-A 26행 | 지배주주순이익 ÷ 기말 자본총계 |

### 근거 — 실측 3건

**(1) DART `M211550`은 회사 기준을 반영하지 않는 고정 산식이다**

```
M211550 = 당기순이익(연결 전체) ÷ ((전기말 자본총계 + 기말 자본총계) / 2) × 100
```

비금융 14종목 + 금융 10종목 = **24/24 재현**(오차 0.02%p 이내). 업종·회사 무관하게 하나의 식이다. 금감원이 XBRL 원장에서 직접 계산한 파생값이며, 회사가 공시한 ROE와는 별개다(KB금융 9.682 vs 공시 9.93).

**(2) 이띠 요구사항 문서는 "지배주주·기말 기준"을 명시하고 있다**

- `../../../ete-django/docs/itti-whole-requirements/이띠_투자자앱_목업_v21.5_기간주제_관심종목캘린더.html`
  → 재무비율 카드: `ROE (지배주주·기말 기준) 10.4%` · `2025 · 연결` · "DART 재무제표 기반 산출"
- `../../../ete-django/docs/itti-whole-requirements/이띠_앱전체_목업기반_상세구현명세_별도부록_v1.0.docx`
  → V-08 재무비율: **"ROE·EPS 지배주주 기준 우선"**

목업의 `10.4%`는 삼성전자 FY2025를 지배기업 소유주 귀속 기준으로 계산한 **10.431**과 일치한다. 다른 후보는 어긋난다(DART 10.783 / 엑셀식 10.14).

**(3) 그런데 연구원 엑셀은 분모가 다르다**

`금융업 발라내기.xlsx` FS-A 시트(KB금융 2013~2025, 13개 연도)를 역산하면 `지배주주 당기순이익(22행) ÷ 자본총계(43행)`가 **13/13 일치**한다(최대 잔차 0.0040%p, 저장 정밀도 ±0.005 이내). 경쟁 후보는 배제된다 — 평균 자본총계 0/12, 자본총계−신종자본증권 6/13(그 6개는 신종자본증권 잔액이 0인 2013~2018년뿐).

> ⚠️ **FS-A 시트에는 수식이 없다**(수식 셀 0개). 위 산식은 값 적합으로 추론한 것이며 원 작성자 확인은 받지 않았다.

즉 **분자는 지배주주 몫, 분모는 비지배지분을 포함한 자본총계**인 혼합 기준이다. 이띠 내부에서 명세와 산출물이 어긋나 있다.

### 무엇을 하지 않는가

- **ROA는 건드리지 않는다.** 현행 `당기순이익(총액) ÷ 자산총계`가 이미 요구사항과 맞다(목업 `8.0%` ↔ 실측 7.974, 유일하게 8.0으로 반올림). 목업에서 ROA에는 기준 라벨이 아예 없어 총액 기준임이 확인된다. 애초에 DART가 순이익 기준 ROA를 제공하지 않아(`M212000`은 총자산**영업이익**률) 처음부터 자체 계산이었고, 그래서 이번 문제를 비켜갔다.
- **금융업 공시 ROE 발라내기는 범위 밖.** 원문 「5. 재무건전성」에서 뽑을 수 있음을 확인했으나(KB금융 5/5 일치) 원문 파서가 필요하고, vintage마다 소급 재작성되는 문제(2022년 9.24 → 8.10)가 별도 설계를 요한다. v5 이후.
- **한 차트에 3개 선을 겹치지 않는다.** 사유는 R1 (c) 참조.

## R1 — ROE 산정기준 3종 병기

**목표** ⑤ 수익성 섹션에 산정기준별 ROE를 나란히 놓고, 각 차트에 산식·원천을 붙여 이띠가 화면만 보고 기준을 고를 수 있게 한다.

### (a) 지표 정의 — K-IFRS 표기 기준

| 지표 키 | 화면 라벨 | 산식 |
|---|---|---|
| `roe` (기존) | ROE — DART 산출 · 평균 자본총계 기준 | `M211550` 직독 |
| **`roe_owners`** (신규) | **ROE — 지배기업 소유주 귀속 기준** | 지배기업 소유주 귀속 당기순이익 ÷ 기말 지배기업 소유주 귀속 자본 × 100 |
| **`roe_owners_on_total_equity`** (신규) | **ROE — 지배기업 소유주 귀속 손익 ÷ 자본총계** | 지배기업 소유주 귀속 당기순이익 ÷ 기말 자본총계 × 100 |

`account_id`는 전부 카탈로그에 이미 있다 — 신규 등록 불필요.

```
분자  ifrs-full_ProfitLossAttributableToOwnersOfParent   catalog.ts:76  net_income_attributable_to_owners
분모  ifrs-full_EquityAttributableToOwnersOfParent       catalog.ts:36  equity_attributable_to_owners
분모  ifrs-full_Equity                                   catalog.ts:34  total_equity
```

**폴백** — 연결재무제표를 작성하지 않는 회사(앱클론 등 OFS 전용)는 지배/비지배 구분이 존재하지 않는다. 이 경우 두 값이 정의상 같으므로 총액으로 대체하고 caveat를 남긴다.

```
분자  net_income_attributable_to_owners → 없으면 net_income        (실측 15/17 제공)
분모  equity_attributable_to_owners     → 없으면 total_equity      (실측 16/17 제공)
```

비지배지분(`ifrs-full_NoncontrollingInterests`)은 **카탈로그에 추가하지 않는다.** 위 폴백으로 전 케이스가 덮이고, 차감식(`자본총계 − 비지배지분`)은 신라젠처럼 비지배 행 자체가 없는 회사에서 오히려 분기 처리를 늘린다.

**세 번째 차트(엑셀 방식)를 넣는 이유**는 이띠 내부의 명세↔산출물 불일치를 화면에서 바로 보여주기 위해서다. 대면미팅에서 "명세는 지배기업 소유주 귀속 자본, 엑셀은 자본총계인데 어느 쪽으로 갈까요"를 숫자와 함께 물을 수 있다. 기준이 확정되면 이 차트는 제거한다.

**한 차트에 3개 선을 겹치지 않는다.** `LineChart`는 단일 시리즈 전용이고, `components/charts/LineChart.tsx:24-30`에 다중 `<Line>` 사용 시 **XAxis 눈금 라벨이 시리즈 개수만큼 중복 렌더**된 실측 함정이 기록돼 있다. 각 차트에 산식 패널이 개별로 붙어야 해서 분리가 설명력도 낫다. 오버레이 비교는 v5 이후.
