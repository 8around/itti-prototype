## Context

### 왜 바꾸는가

사용자 지적: *"차트 모양이 사람이 볼 때 보기 힘들 수준으로 박살이 나있다. 색상·모양 등 퀄리티를 높이고, 차트에 나타나는 값을 어떻게 그렸는지 산식과 논리구조를 설명할 수 있으면 좋겠다."*

v2는 **데이터 정합성**(분기 축, Q4 역산, 기수 페어링, 승인규칙 4종)을 세웠지만 **시각 표현**은 목업에서 이식한 값을 그대로 뒀다. 브라우저 실측으로 원인이 특정됐다.

**A. 색 — 흑자가 안 보이고 적자만 보인다 (가장 큰 원인)**

| 대상 | 색 | 흰 배경 대비 | 문제 |
|---|---|---|---|
| `.qbfill`/`.zbf` 양수 막대 | `#c5cec7` **하드코딩** | **1.61:1** | 앱에서 가장 많이 쓰이는 막대색이 거의 안 보임 |
| `.zbbot .zbf` 손실 막대 | `var(--up)` | 4.98:1 | 손실만 선명 → **비대칭 인상** |

| `.fill.neg` 현금 유출 | `#a9c5e3` **하드코딩** | 1.78:1 | 유입(5.13:1) 대비 존재감 없음 |
| `--chart-2`/`--chart-5` | `#6baf7e`/`#b4cbd9` | 2.61 / 1.68 | 팔레트 5색 중 초록 2종·청회 2종이 hue 근접 |

**B. 기하 — 모바일 목업 치수를 데스크톱에 그대로 이식**

목업 `../../../ete-django/docs/goals-in-2months/이띠_R1_배포앱_목업_6.html:150`의 `.bars{height:82px}`는 **375px 폰 화면 기준**이다. 이 값이 `SIGNED_AXIS_TOTAL_PX=82`(`components/charts/chartUtils.ts`)와 `.qbtrack`/`.sbatrack{height:86px}`로 그대로 넘어와, 실제 렌더는 **820px 폭 × 82px 높이 = 10:1**이 됐다. 정본인 학습가이드 `bars()`는 `viewBox 300×110~130`(≈2.5:1)이다.

- 막대 폭 **상한이 없다** → 3개 연도면 150px 뚱뚱한 블록, 8분기면 얇은 조각. 학습가이드는 `bw = Math.min(34, slot*0.55)`
- `LineChart`는 `viewBox 236×70` + `preserveAspectRatio="none"` → 820px에 늘어나며 가로 왜곡, 선이 상단에 잘림. 학습가이드 `line()`은 `pad=(hi-lo)*0.25` 도메인 여백이 있다
- **축·눈금·그리드가 전무하다** — 12종 어디에도 Y축 눈금이 없어 막대 높이를 수치로 환산할 수 없다
- 이상치가 스케일을 독점 (삼성 26.1Q 영업이익 57.2조 vs 나머지 4.6~12.1조 → 7개 막대가 5~15px로 뭉개짐)

**C. 타이포 — 값·축 라벨이 6.5~9px**

실사용 8분기 화면은 `compactLabels`가 상시 켜져 축 라벨 **6.5px**, 값 **7px**까지 내려간다. 공간이 부족하면 회전이나 생략 없이 폰트만 계속 줄이는 전략이고, `overflow`/`ellipsis` 처리도 없어 좁은 폭에서 이웃과 겹친다. `@media` 쿼리는 전 CSS에 **0건**이다.

**D. 차트가 출처 카드에 파묻힌다**

`QuarterSourceRow`(`app/stock/[code]/page.tsx:343-376`)가 **분기 차트 1개당 최대 8개**의 개별 출처 카드를 나열한다.

| 프로필 | ② 손익 섹션 | 페이지 전체 |
|---|---|---|
| STANDARD(삼성전자) | 차트 8개 + 출처 카드 ~56개 → **3,630px** | `<details>` **114개**, 세로 **7,714px** |
| FIN_HOLDING(KB금융) | 6지표×3차트×8분기 = 최대 **144개** | 200개 이상 추정 |

모바일(325px)에서는 페이지가 **14,354px**로 늘고 값 라벨이 서로 겹친다.

**E. 산식이 3단계 뒤에 숨어 있다**

`derivation` 문자열은 12종 패턴으로 `lib/normalize/derive.ts`·`engine.ts`·`resolve-alotmatter.ts` 3파일에만 생산돼 구조가 깔끔하다. 그러나 —

- `MetricValue`는 `derivation`을 **받지도 않는다** (화면 숫자 옆에 산식이 절대 안 나옴)
- 유일한 노출은 SourcePanel을 펼치고 → "파생 계산식" 탭을 클릭해야 보이는 `DerivationTab`
- 내용은 **원 단위 raw 숫자 그대로**: `"Q4 = 300,870,903,000,000 − 225,082,634,000,000"` — 사람이 억원으로 환산해야 함
- `ProfileMetric` 카탈로그에 산식/설명 필드가 없어, 필요한 곳만 라벨 문자열에 임기응변으로 끼워 넣음 (`app/stock/[code]/page.tsx:851` ROA 라벨)

### 불변 제약 (v2 리뷰가 지킨 것 — 재작성 중 깨뜨리면 회귀)

1. **클라이언트 승인 규칙**: ① 손실 분기는 기준선 아래 ② 잠정치(Q4 역산·CF 차분)는 점선 ③ 적자 PER N/A ④ 배당 0원(`ZERO_BY_FACT`) vs 데이터 없음(`MISSING`) 구분
2. **정규화 레이어 무손상** — `lib/normalize/**`의 값(`normalized`·`displayState`)은 변경 금지. 테스트 151개 중 ~140개가 이 레이어이며 그대로 통과해야 한다 (차트 내부를 테스트하는 건 `components/charts/chartUtils.test.ts` 하나뿐)
3. **근거 없는 값 금지** — 불확실하면 MISSING + derivation
4. API 키 평문 노출 0 · SSG 20종목 유지

### 기술 확인 (Context7 실조회)

Recharts **v3.3.0** — React 19 / Next.js SSR 지원 확인. 필요한 기능이 전부 있다:

- `Bar`의 `shape` prop + `BarShapeProps`/`BarRectangleItem` 타입 → **막대별 커스텀 렌더**(잠정치 점선, 손실 적색, 결측 회색)를 per-bar로 처리
- `CartesianGrid`·`XAxis`·`YAxis` → 지금 없는 축·눈금·그리드
- `label` prop 커스텀 렌더러 → 값 라벨
- `isAnimationActive={false}` → SSG·스크린샷 결정성
- 워터폴은 range dataKey `[bottom, top]` 패턴(공식 예제 존재) → `PnlWaterfall` 이식 가능

현 스택: Next 16.3.0 · React 19.2.8 · vitest 4.1.10 · pnpm 11.21.0 · Tailwind 미사용.

## V1 — 막대 계열 3종 재작성

가장 많이 쓰이고 가장 많이 망가진 축. `ZeroAxisBars`(매출·영업이익·순이익·EPS·금융 6종) → `StackedBarsAbs`(재무상태) → `OverlaidBars`(EPS+DPS).

- **0축 막대**: `BarChart` + `CartesianGrid`(가로선만) + `XAxis` + `YAxis`(눈금·단위) + `ReferenceLine y={0}`. 손실은 자동으로 0축 아래로 내려간다 — **`signedAxisScale`의 수동 px 배분은 라이브러리 스케일로 대체되어 퇴역**
- 막대별 상태는 `Bar shape={...}`로 처리: 확정=채움 / **잠정=점선 테두리 + 연한 채움**(승인규칙 2) / 손실=적색 / 결측=렌더 안 함(0으로 그리지 말 것)
- 값 라벨은 `label` 커스텀 렌더러. 막대가 짧으면 막대 밖에 표기
- 누적 막대: `Bar stackId` 사용. 자본=초록/부채=적색(학습가이드 `stacked()` 정본, 부채 opacity .55). **세그먼트별 값이 현재 `title` 툴팁에만 있어 터치 기기에서 접근 불가** → Recharts `Tooltip`으로 해소
- 오버레이 막대: EPS 바깥 + DPS 안쪽. 적자 연도 DPS 분리 표기와 `ZERO_BY_FACT`("무배당") vs `null`("—") 칩 구분은 **현행 동작 그대로 이식**(승인규칙 4)

**검증** 삼성전자 8분기 막대에 Y축 눈금·그리드 존재 · 헬릭스미스 손실 분기 0축 아래 · 25.4Q 잠정 점선 · LG화학 음수 EPS 하향 · 앱클론 "—" vs 헬릭스미스 "무배당" 유지 · 이상치(삼성 26.1Q)가 있어도 나머지 7분기 높이 비교 가능
**규모** 1.5일 · **선행** V0

## V2 — 꺾은선 + 부호 그룹막대

- `LineChart` 재작성: `preserveAspectRatio="none"` 왜곡 제거. **Y 도메인에 데이터 범위 25% 여백**(학습가이드 `line()`) → 선이 상단에 잘리는 현상 해소. `baseline`(성장률 0% / 부채비율 100%)은 `ReferenceLine`으로, 도메인 포함 보장 유지
- 부채비율처럼 기준선이 데이터에서 멀면 지금은 차트 3/4가 빈 공간 — 도메인 계산이 기준선과 데이터를 **함께** 담되 데이터 쪽 해상도를 확보하도록
- 잠정 구간 점선은 `buildLineRuns`가 이미 푼 문제다. Recharts로 옮길 때 **"첫 잠정 이후 끝까지" 회귀를 재발시키지 말 것**(v2 M5에서 고친 항목) — 구간별 판정 유지
- 전환 상태(흑자전환/적자전환/적자지속) 칩은 `MetricValue.renderText()` 문구를 그대로 전달, **새 문구를 짓지 말 것**
- 수치 포인트 0개(전 구간 전환)여도 축·기준선·안내 문구 유지 (v2 개선점 B)
- `SignedGroupedBars`(현금흐름): 9px 얇은 막대 3계열 → 폭 확보 + 의미색 3종 + **값 라벨 신설**(현재 라벨이 아예 없어 색 대조로만 추정)

**검증** 삼성 ROE·영업이익률 꺾은선 선이 잘리지 않음 · 부채비율 100% 기준선과 데이터가 함께 판독 가능 · 헬릭스미스 QoQ 전 구간 전환 상태에서도 축 유지 · 삼성 24년 투자CF(−85.38조) 막대가 영업CF(+72.98조)보다 큼
**규모** 1.5일 · **선행** V0

## V5 — 산식 설명 레이어 (화면 + 문서)

**목표** *"이 막대가 어떻게 나온 값인지"*를 화면에서 즉시, 문서로 상세히 설명 가능하게.

**(a) 구조화 — `Resolution`에 additive 필드**

현재 `derivation`은 이미 포맷된 문자열이라 화면에서 억원 환산이 불가능하다. 문자열을 **파싱하지 말고**, 생산 시점에 구조를 함께 남긴다.

```ts
// lib/normalize/types.ts (additive — 기존 derivation 문자열은 유지)
export type DerivationDetail = {
  kind: "q4_reverse" | "cf_diff" | "growth" | "ratio" | "fcf" | "dividend_payout_fallback";
  resultLabel: string;                                   // "24.4Q 영업이익"
  steps: { label: string; value: number; op?: "minus" | "div" | "mul" }[];
  unit: "KRW" | "PCT" | "X";
  caveat?: string;                                       // "가중평균주식수 변동으로 근사치"
};
```

생산처는 3파일뿐이라 범위가 좁다: `derive.ts`(패턴 9종) · `engine.ts`(EPS Q4 주의문) · `resolve-alotmatter.ts`(배당성향 fallback).

**(b) 화면** — 차트 하단 `▼ 이 차트의 값은 이렇게 계산됐습니다` 접기(V4의 단일 collapse에 통합). 억원 환산 + 한글 지표명으로 렌더:

> `24.4Q 영업이익 6조 4,927억 = 2024 사업보고서 연간 32조 7,260억 − 2024 3분기보고서 누적 26조 2,332억`
> `⚠ 역산값이라 잠정 표시(점선)`

**(c) 카탈로그** — `ProfileMetric`(`lib/profiles.ts:14-31`)에 `formula?`/`description?` 필드 추가. `app/stock/[code]/page.tsx:851` ROA 라벨처럼 라벨 문자열에 박아둔 계산식을 정식 필드로 이관

**(d) 문서** — `docs/specs/2608_metric-formulas.md`. 산식뿐 아니라 **논리구조**를 담는다:
